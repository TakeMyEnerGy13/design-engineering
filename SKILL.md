# Design Engineering

Оркестратор дизайн-работы. Сам не переизобретает генерацию — задаёт **якорь вкуса**
и anti-slop рамки, а сборку отдаёт `frontend-design`, полировку (по запросу) — `impeccable`.

Без якоря вкуса любой UI получается безликим («чуть менее кричащий слоп»). Поэтому
этап 1 — обязательный гейт, его нельзя пропускать.

## Scope — сначала выбери путь

- **Новый UI** (экран, страница, компонент с нуля, новый проект) → полный флоу ниже.
- **Правка существующего UI** (консистентность, точечная стилизация в зрелом проекте) →
  якорь уже материализован в коде: прочитай соседние компоненты, извлеки их паттерн
  (variants, токены, scale) и назови якорь явно перед правкой («якорь: кнопки тулбара,
  variant=outline size=sm»). `design.md` создавать не нужно (но если есть — он главнее).
  Anti-slop, core и провижининг ассетов (шаг 3) действуют как обычно. Если соседний
  паттерн сам нарушает anti-slop (эмодзи-иконки, случайные отступы) — не копируй его
  молча: скажи пользователю и предложи поправить.

## Флоу (новый UI)

### 1. Якорь вкуса — ОБЯЗАТЕЛЬНЫЙ ГЕЙТ
Найди `design.md` в корне проекта.

- **Есть** → используй его как якорь, иди к шагу 2.
- **Нет** → НЕ верстай вслепую. Сначала зафиксируй вкус:
  1. **Сначала проси референс — лучше скриншотом, чем ссылкой.** «Кинь скриншот продукта/сайта, чей вид тебе близок.» Скриншот модель видит и метит прямо в него — это сильнее текстового описания. Ссылка/название — приемлемый, но более слабый вариант.
  2. **Фоллбэк, если референса нет** — 2-3 быстрых вопроса: тема (dark/light), настроение в 3 словах, плотность (плотный/воздушный).
  3. Запиши результат в `design.md` из `project-template.md`. Это и есть проектный слой.

**Получил скриншот →** снимай с него ДНК стиля в поля шаблона: эстетика-якорь (ориентир,
настроение в 3 словах), палитра (нейтральная база, акценты, тема), типографика, плотность.
Не копируй продукт пиксельно.

**Цейтнот / «не задавай вопросов» →** гейт ≠ допрос. Если спросить нельзя — выбери якорь
САМ: конкретный ориентир + параметры (база, акцент, плотность, шрифт), назови его в ответе
(«беру плотный dark в духе Linear: нейтральная база, один акцент») и зафиксируй минимальным
`design.md` (3-5 строк по шаблону) ПЕРЕД вёрсткой — это секунды, а якорь переживёт сессию.
Запрещены безымянные и абстрактные дефолты («современный стиль», «нейтрально») — на практике
они всегда сводятся к indigo-градиентам и карточкам-штампам, т.е. ровно к тому slop, от
которого скилл защищает. Полный `design.md` допиши после.

Не переходи к генерации, пока якорь не назван — пользователем или тобой.

### 2. Правила
Прочитай `design-core.md` и `anti-slop.md` из папки этого скилла.

### 3. Ассеты — провижининг ПЕРЕД генерацией
Slop часто = модель импровизирует, потому что ей нечем работать (нет иконок → эмодзи,
нет компонентов → самодельные кривые). Закрой это до вёрстки:
- **Иконки:** проверь `package.json` на icon-библиотеку (`lucide-react` / `@phosphor-icons/react`).
  Нет → предложи поставить. НИКОГДА не используй эмодзи как иконки (см. anti-slop п.1) —
  если библиотеки нет и ставить нельзя, используй inline SVG или текст/инициалы, но не эмодзи.
- **Шрифт:** есть ли осознанный шрифт, или дефолтный системный? Подтяни из якоря:
  подключи (CSS `@import` / next-font / `<link>`) и пропиши в конфиге (Tailwind
  `fontFamily` или CSS-переменная).
- **Компоненты:** если в проекте есть UI-набор (shadcn и т.п.) — собирай из него, не изобретай.
- **Motion:** простые интеракции (press/hover) — на CSS/Tailwind, без зависимостей. Если нужна сложная анимация (вход/stagger/spring) — предложи поставить пакет `motion` (преемник framer-motion, импорт из `motion/react`). См. `motion.md`.

### 4. Генерация
Вызови скилл `frontend-design` (Skill tool) в этом же контексте — якорь, core и anti-slop
уже в контексте, отдельной «передачи» не нужно. design-engineering сам генерацию не дублирует.

### 5. Полировка — ТОЛЬКО ПО ЗАПРОСУ
Не запускай автоматически. Если пользователь просит «отполируй / доведи / аудит UI» —
прогони через `impeccable`.

## Приоритет правил
`явная инструкция пользователя` → `проектный слой (design.md)` → `core / anti-slop`.

Приоритет пользователя относится к **эстетическим решениям**: просит glassmorphism,
градиент, центрирование — делай и не спорь, anti-slop — дефолты, не табу.
Он НЕ отменяет процесс: «без вопросов / срочно» включает режим цейтнота из шага 1
(сам выбери и назови якорь), а не вёрстку без якоря.

## Red flags — рационализации, которые означают «стоп»

| Рационализация | Реальность |
|---|---|
| «Юзер сказал "без вопросов" — гейт отменён» | Отменён допрос, не якорь. Выбери якорь сам, назови его явно — это 0 лишних секунд. |
| «Возьму нормальные нейтральные дефолты, это не слоп» | Безымянный дефолт = indigo + rounded-2xl + shadow + border. Это и есть слоп (anti-slop п.2, п.3). |
| «Это просто одна кнопка» | Тогда это правка существующего UI (см. Scope): якорь = соседний код. |
| «Стиль и так очевиден из проекта» | Отлично — это и есть якорь. Прочитай код, извлеки паттерн явно (не «по памяти»); для нового UI перенеси его в `design.md`. |
| «Дедлайн, процесс — активный вред» | Режим цейтнота встроен в гейт и не стоит времени. Вред — переделывать слоп после демо. |

## Codex / другие агенты
`design-core.md` и `anti-slop.md` — портативный markdown, читаются явной командой вне Claude Code.
